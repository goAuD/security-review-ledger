# v0.1.1 — evidence precision

The `v0.1.1` tag includes more precise evidence recording and a linked scenario matrix. The published `v0.1.0` tag and installations pinned to it remain unchanged.

## Changes

- Add a compact requirement/hypothesis table and scenario matrix to the ledger template.
- Distinguish an attempted check, execution of the target behavior and completion of the relevant assertion or comparison.
- Keep observations with missing expectations separate from confirmed findings and accepted behavior.
- Prefer the project's documented runtime or existing environment, and preserve the procedure behind each evidence artifact.
- Explain authorized local storage for private reviews and the limits of ignore rules.
- Include the post-`v0.1.0` example clarifications and five-test suite, including forged query and header inputs on permitted reads, while preserving earlier review attempts.

Existing scenario states and historical ledger records remain valid. Existing ledgers can add the new indexes without rewriting their earlier attempts. No runtime dependency is added.

## Installation

Install this version from the project to review:

```sh
npx --yes skills@1.7.6 add goAuD/security-review-ledger@v0.1.1 --skill security-review-ledger
```

## Verification

Local verification on 2026-11-06 used Windows and Node.js 22.23.4:

| Check | Result and boundary |
| --- | --- |
| Existing recipe example | All five tests passed using `node --test --test-reporter=tap examples/recipe-access/read-recipe.test.mjs`. This checks the example, not all agent behavior. |
| Paired Codex trials | Two synthetic cases, each run once with the previous instructions and once with the candidate, in separate agent contexts. Both versions correctly handled skipped execution, an unresolved refresh expectation, historical evidence and a changed-contract violation. |
| Output review | Eight stated criteria per case: candidate 16/16; baseline 14/16. Both baseline misses were the compact expectation/state/evidence matrix. This is an observed traceability improvement, not evidence of generally better defect detection. |
| Source and artifact checks | Local Markdown file links, UTF-8/LF formatting, preserved frontmatter and synthetic-input hashes checked. The previous and candidate instruction packages were retained with content digests. |
| Optional skill validator | The `skill-creator` validator exited before validation because PyYAML was absent. No dependency was installed. The unchanged frontmatter and the separate local checks above were verified; a full YAML parse was not performed. |

The prompts, fixtures, raw command results, ledgers, grading and HTML comparison are retained in the maintainer's ignored local evaluation workspace. No private application findings were copied into the distributable skill. One trial per case/version does not establish repeatability; full executor time and token metrics were unavailable and were not estimated. Runtime-recovery and private-location selection were not independently exercised: these trials supplied Node and explicit isolated output locations.

An agent trial does not establish complete security coverage, consistent behavior across models or actual Claude Code compatibility.
