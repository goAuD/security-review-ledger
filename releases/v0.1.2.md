# v0.1.2 — standards references and review evidence

When a reviewer asks which standard applies, a scenario can now link the published requirement to a specific check or open question. In the recipe example, OWASP ASVS describes who may read a record. The project's own requirement specifies the exact 404 response and JSON body. [Worked example](https://github.com/goAuD/security-review-ledger/blob/v0.1.2/examples/recipe-access/review.md#sr-002)

## Changes

- Fix the OWASP ASVS 5.0.0 release link and link directly to the data-access requirement in the tagged edition. [OWASP ASVS v5.0.0-8.2.2](https://github.com/OWASP/ASVS/blob/v5.0.0_release/5.0/en/0x17-V8-Authorization.md#v82-general-authorization-design)
- Add NIST SSDF 1.1 task PW.7.2 for source review alongside PW.8.1 and PW.8.2 for executable tests. The ISO/IEC 27034-1 public overview provides context for setting the scope. [Standards references](https://github.com/goAuD/security-review-ledger/blob/v0.1.2/skills/security-review-ledger/references/standards.md)
- Add an optional standards mapping to the ledger template. Existing ledgers can adopt it when they next review a relevant scenario.
- Index all six recipe scenarios in a matrix. Real session binding and shared-cache behavior remain open integration questions. [Scenario matrix](https://github.com/goAuD/security-review-ledger/blob/v0.1.2/examples/recipe-access/review.md#scenario-matrix)

## Installation

From the project you want to review, install the versioned skill and choose your agent when prompted.

```sh
npx --yes skills@1.7.6 add goAuD/security-review-ledger@v0.1.2 --skill security-review-ledger
```
